## 1. Audit Objective

Investigate the reported routing defect where user queries referencing two or more temples are routed to `ComparisonAgent` even when the user explicitly requests a multi-day or multi-temple itinerary.

Reported user examples:
1. `"itinerary for Basara and Vemulawada"`
2. `"plan an itenary of 2 days to visit Birla Mandir and Ujjaini"`

Expected behavior:
```text
Explicit itinerary intent + multiple temples
    → ItineraryPlanningAgent
```

Observed behavior in UI:
```text
Explicit itinerary intent + multiple temples
    → ComparisonAgent
```

This audit determines the exact architectural root cause in `backend/app/agents/router.py`, evaluates `ItineraryPlanningAgent`'s existing multi-temple capability, analyzes comparison and multi-intent backward compatibility, and formulates a minimal, zero-breakage recommendation.

## 4. Root Cause Analysis

### 1. Precedence Inversion Between Priority 3 and Priority 4
In `AgentRouter.route()`, **Priority 3 (Comparison Intent)** is evaluated before **Priority 4 (Itinerary Planning Intent)**.
Priority 3 includes the boolean condition:
```python
if is_comparison_syntax or len(detected_temples) >= 2:
```
Because `len(detected_temples) >= 2` evaluates to `True` for any multi-temple query, the router branches into Priority 3 immediately.

### 2. Multi-Intent Exception Guard Was Insufficient for Pure Multi-Temple Itineraries
Priority 3 attempts to protect conjoined multi-intent queries using:
```python
sub_intents = self._detect_multi_intent(clean_query)
non_comp_intents = [si for si in sub_intents if si != "comparison"]
if len(non_comp_intents) >= 2:
    return AgentRouteDecision(intent="multi_intent", ...)
```
When a query asks for an itinerary AND food (e.g. Query #10), `non_comp_intents` detects `['prasadam', 'itinerary']` ($\ge 2$), successfully escalating to `multi_intent`.
However, when a query asks **purely for a multi-temple itinerary** (e.g. *"Plan an itinerary for Basara and Vemulawada"*):
* `sub_intents` contains only `['itinerary']` (length = 1).
* Therefore, `len(non_comp_intents) >= 2` is `False`.
* Priority 3 treats the query as a `comparison` intent.
* Execution returns early at line 214 and **never reaches Priority 4**.

---

## 5. Comparison Compatibility

The routing principle demands that legitimate comparison queries continue routing to `ComparisonAgent`:

1. **Explicit Comparison Queries** (e.g., *"Compare Basara and Vemulawada"*, *"Compare accommodation between Srisailam and Bhadrachalam"*):
   - Trigger `is_comparison_syntax = True` (`compare`, `versus`, `vs`, `difference between`).
   - Do **not** match `_itinerary_patterns`.
   - Will continue routing to `ComparisonAgent`.

2. **Implicit Comparison Queries Without Itinerary Intent** (e.g., *"Basara and Vemulawada facilities"*):
   - `len(detected_temples) >= 2`.
   - Do **not** match `_itinerary_patterns`.
   - Will continue routing to `ComparisonAgent` as the fallback handler for multi-temple property questions.

Therefore, carving out an exception for explicit itinerary patterns will have **zero negative impact** on existing comparison queries.

---

## 6. Multi-Intent Compatibility

Multi-intent handling via `SequentialMultiIntentPipeline` remains completely intact:
* Compound queries like *"What are the timings of Basara and plan a 2-day itinerary for Basara and Vemulawada?"* or *"Plan a 2-day tour to Yadadri and Dharmapuri including food"* contain two distinct sub-intents (`timings` + `itinerary`, or `prasadam` + `itinerary`).
* Both Priority 3 and Priority 4 include explicit multi-intent escape hatches that route `len(sub_intents) >= 2` directly to `intent="multi_intent"`.
* The multi-intent pipeline splits and delegates sub-queries sequentially to the respective specialist agents (`temple_information` + `itinerary_planning`), and `ResponseAggregator` synthesizes the final composite response.

## 8. Typo Analysis (`"hich temples provide free Annadanam?"`)

* **Query**: `"hich temples provide free Annadanam?"`
* **Trigger evaluated**:
  The aggregation regex in `_aggregation_patterns` matches:
  `r"\b(which\s+(all\s+)?temples)\b"`, `r"\b(list\s+temples)\b"`, etc.
* **Result**:
  Because of the typo `"hich"` instead of `"which"`, the aggregation trigger failed. With 0 detected temples, the router safely fell into Priority 8 (Clarification Guardrail):
  *"Which temple would you like information about? PilgrimAI currently covers 20 major temples in Telangana..."*
* **Classification**:
  This is **expected guardrail behavior**, not a routing defect. The system correctly refuses to hallucinate when an intent pattern is broken and no specific temple is identified.

## 9. Regression Risk

If router precedence is adjusted, the primary risk is inadvertently breaking queries where a user asks to compare two temples.
* **Risk Mitigation**:
  The adjustment must **only** redirect multi-temple queries when `is_itinerary_syntax` is explicitly `True`.
  If `is_itinerary_syntax` is `False`, the query must remain routed to `ComparisonAgent`.

## 10. Recommended Minimal Fix (Router-Only)

In [backend/app/agents/router.py](file:///D:/pligrim%20ai%20new/backend/app/agents/router.py), modify Priority 3 so that `len(detected_temples) >= 2` does **not** swallow queries that explicitly match `self._itinerary_patterns`.

### Current Code (Lines 195–196):
```python
is_comparison_syntax = any(re.search(p, clean_query, re.IGNORECASE) for p in self._comparison_patterns)
if is_comparison_syntax or len(detected_temples) >= 2:
```

### Proposed Minimal Edit:
```python
is_comparison_syntax = any(re.search(p, clean_query, re.IGNORECASE) for p in self._comparison_patterns)
is_itinerary_syntax = any(re.search(p, clean_query, re.IGNORECASE) for p in self._itinerary_patterns)

# Route to comparison if explicitly requested, or if 2+ temples are mentioned without itinerary intent
if is_comparison_syntax or (len(detected_temples) >= 2 and not is_itinerary_syntax):
```

### Why This Fix Is Safe and Minimal:
1. **Zero change to comparison queries**: Queries like `"Compare Basara and Vemulawada"` or `"Basara and Vemulawada facilities"` have `is_itinerary_syntax = False`, so they continue routing to `ComparisonAgent`.
2. **Zero change to single-temple queries**: Single-temple queries have `len(detected_temples) == 1`, so Priority 3 does not match unless explicit comparison syntax is present.
3. **Zero change to multi-intent queries**: Multi-intent conjoined checks continue to execute normally.
4. **Fixes multi-temple itineraries**: Queries like `"Plan an itinerary for Basara and Vemulawada"` bypass Priority 3 and fall through to Priority 4 (`itinerary_planning`), which correctly invokes `ItineraryPlanningAgent`.
5. **No changes required in any agent or RAG layer**: `ItineraryPlanningAgent`, `ComparisonAgent`, and `MasterAgentCoordinator` remain 100% untouched.
